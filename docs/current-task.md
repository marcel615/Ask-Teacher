- [2026-11-09 사용자 댓글](https://github.com/marcel615/Ask-Teacher/issues/58#issuecomment-6735724695): JWT STATELESS, 토큰 수명과 회전·재사용 차단, 단일 세션·즉시 무효화, Redis fail-closed, API·CSRF·CORS와 인증 구조 개선 범위를 결정했다.
- 이후 사용자 대화 결정: 사용 완료된 현재 세션의 Refresh Token 재사용 시 즉시 세션을 폐기한다. React에서 재발급 단일 요청 및 탭 간 조정을 수행하고 응답 유실 시 재로그인을 권고한다. 로그아웃은 CSRF 실패 403, Redis 장애 503이 우선이며 그 외에는 가능한 쿠키 정리 후 204를 반환한다. 서버를 먼저 구현하고 React는 별도 후속 작업으로 다룬다.
- 사용자는 상세 설계와 이 문서의 작성 및 구현을 승인했다. 단일 개발 Redis를 대상으로 하며 운영 영속화·복제·백업과 복원 시 세션 부활 방지는 별도 작업이다.
- 이후 사용자 대화에서 공개 JWT 기본 서명 키 제거와 `JWT_SECRET` 환경 변수로 안전한 키를 필수 제공하는 변경을 추가 승인했다. 기존 토큰은 재로그인이 필요하며 실제 비밀값은 기록하거나 출력하지 않는다.

## 목표와 범위

- 기존 회원가입을 유지하고 로그인과 `POST /api/auth/refresh`, `POST /api/auth/logout`, `GET /api/auth/csrf`를 결정된 계약에 따라 구현한다.
- Access Token은 15분, Refresh Token은 회전마다 최대 7일이며 최초 로그인부터 최대 30일이다. 로그인과 재발급 응답은 `accessToken`, `tokenType`, `expiresIn`(초)을 포함하고 Refresh Token은 HttpOnly 쿠키로만 전달한다. 재발급 요청에는 본문을 사용하지 않는다.
- 사용자당 단일 세션을 유지한다. Access Token의 사용자·권한 및 세션 식별자를 검증하고 Redis의 현재 세션과 비교해 새 로그인, 로그아웃 또는 재사용 감지 시 기존 토큰을 즉시 무효화한다. 교체된 과거 세션의 토큰은 현재 세션을 폐기하지 않고 거부한다.
- 난수 기반 Refresh Token의 평문을 저장하거나 기록하지 않고 해시를 비교한다. 현재 세션의 사용된 토큰 이력을 검증해 재사용 시 해당 세션을 폐기한다. 이력의 수명·증가량을 제한할 때 차단 정책을 약화하지 않으며, 한도 초과 시 안전하게 재로그인을 요구한다.
- 세션 교체·회전·로그아웃·재사용 감지의 Redis 연산을 원자적으로 처리한다. 동시에 같은 토큰을 제출하면 두 번째 사용은 재사용으로 판정될 수 있다. 응답 유실에 대한 서버 측 재발급 유예는 두지 않는다.
- `AskTeacherUserDetails`, `AskTeacherUserDetailsService`, `AuthenticationManager` 및 적절한 Provider, 기존 Spring Security `Authentication`과 `SecurityContextHolder`를 사용한다. 기존 `@AuthenticationPrincipal` 사용 코드와 관련 테스트를 수정하며 사용자 ID와 권한의 의미를 유지한다. 비밀번호와 토큰 비밀값을 로그·응답에 노출하지 않는다.
- STATELESS를 유지하면서 비로그인 사용자에게 CSRF 토큰을 발급하고 쿠키 기반 인증 API의 CSRF 보호를 적용한다. 허용 Origin을 명시하고 운영 HTTPS·Secure 쿠키와 환경별 쿠키 속성을 적용한다. 인증 실패 401, 권한 또는 CSRF 실패 403, Redis 장애 503을 구분한다.
- 로그아웃은 유효한 인증 정보로 식별 가능한 세션만 무효화한다. CSRF 검증 실패 또는 Redis 장애가 우선하지 않는 경우 이미 만료되거나 로그아웃한 요청에도 가능한 쿠키 정리 후 204를 반환한다.

## 저장소·환경 및 문서

- Redis에 현재 세션 식별자, 최초 로그인 및 절대 만료 정보, 현재 Refresh Token 해시와 사용 이력을 저장한다. 만료와 정리 정책은 최대 세션 수명 및 재사용 감지 정책에 맞춘다. Redis 통신 실패 시 인증을 허용하지 않고 503으로 처리한다.
- 단일 개발 Redis를 대상으로 compose, 환경 변수 예시와 실행 방법을 반영한다. 실제 비밀값을 저장하거나 출력하지 않는다. 메모리 전용 Redis 재시작 시 세션이 사라져 재로그인이 필요할 수 있다. 운영 영속화·복제·백업 복구에서 오래된 세션이 부활하지 않는다는 보장은 이번 범위에 포함하지 않는다.
- JWT 서명 키는 공개 기본값 없이 `JWT_SECRET`으로 제공받고 누락되거나 안전하지 않은 키는 거부한다. 환경 변수 예시에는 실제 비밀값을 넣지 않는다.
- 요구사항의 기존 재발급 제외 설명과 API 명세의 로그인·인증 계약을 실제 동작에 맞게 갱신하고 Redis 데이터와 수명을 설명한다. 관계형 DB 스키마 변경은 예상하지 않으며 변경이 필요하면 중단한다. 스키마 변경이 없으면 ERD 변경은 필요하지 않다.
- 기존 Access Token은 새 세션 식별자가 없으므로 변경 적용 후 재로그인이 필요하다. React 자동 재발급은 별도 후속 작업이며 서버 기능만으로 구현된 것으로 기록하지 않는다.
