## 목표와 범위

- 삭제된 게시글에 유효한 수정 요청을 보내면 존재하지 않는 게시글과 동일한 `POST_NOT_FOUND` 404를 반환하고 게시글과 첨부파일을 변경하지 않는다.
- 게시글 수정에서 삭제되지 않은 게시글만 조회해 작성자 검증 및 파일 저장 전에 없는 게시글 오류를 반환한다.
- 활성 게시글의 작성자 수정, 타인 거부, 요청·응답과 검증 및 미인증 처리는 유지한다.

## 제외 범위

- 게시글 복구, DB 구조 및 인증·인가 정책 변경, 다른 기능 확장.
- 동시 수정과 삭제의 직렬화 보장 및 첨부파일 저장 실패 전반의 정합성 처리 (#65).

## 요구사항·API·ERD

- `docs/requirements.md`와 `docs/api-spec.md`의 게시글 수정 항목에 삭제된 게시글의 처리 기준을 반영한다.
- Entity와 DB 구조 변경이 없어 `docs/erd.md`는 변경하지 않는다.

## 검증 계획

- 변경 전 결함을 재현하거나 실제 동작을 확인한다.
- Controller의 기존 오류 응답, Service의 삭제·미존재 오류와 파일 저장 미호출, Repository의 삭제 여부에 따른 실제 쿼리를 검증한다.
- 인증부터 DB·파일까지 통합 흐름에서 게시글과 기존 파일을 생성하고 삭제한 뒤 새 파일을 포함한 수정 요청의 404와 오류 메시지를 확인한다. 삭제 직후의 게시글 필드·기존 파일 메타데이터와 실제 파일 및 저장 디렉터리가 요청 후 유지되는지 확인한다.
- 활성 게시글의 작성자 수정 성공과 타인 거부, 미존재 및 미인증 요청을 회귀 검증한다. 테스트 DB와 파일 경로는 개발 환경과 격리하고 정리한다.
- 관련 테스트와 `./gradlew test`를 실행하고 결과와 미검증 사항을 기록한다.
