### 오늘의 작업

- 인증·게시글·카테고리·게시글 좋아요 API의 성공 응답에서 `ApiResponse<T>` 래퍼를 제거했다.
- 후속 승인에 따라 자동 테스트를 실행하고, 변경 API의 `.http` 예시를 갱신한 뒤 수동 API를 확인했다.
- 변경된 성공 응답 형식을 `docs/api-spec.md`에 반영했다.

### 변경 내용

- 데이터가 있는 성공 응답은 기존 DTO 또는 목록을 `ResponseEntity` 본문에 직접 반환한다.
- 회원가입·게시글 작성은 201, 로그인·카테고리 조회·게시글 조회 및 수정은 200을 유지한다.
- 좋아요 등록은 200, 좋아요 취소·게시글 삭제는 204를 반환하며 세 응답 모두 본문이 없다.
- 미사용 `ApiResponse.java`를 별도 승인 후 삭제했다.
- 기존 `.http` 파일의 `response.body.data` 참조와 오래된 게시글 작성 요청 형식을 변경된 API에 맞게 갱신했다.

### 테스트 결과 / 수동 확인 결과

- `./gradlew test`: `BUILD SUCCESSFUL`. `ApiResponse.java` 삭제 후에도 재실행해 통과했다.
- 로컬 18080 포트에서 PowerShell·curl로 수동 확인했다. 회원가입·게시글 작성은 201, 로그인·카테고리·게시글 목록/상세/수정은 200이며 DTO 또는 목록이 본문에 직접 반환됐다.
- 좋아요 등록은 200, 좋아요 취소·게시글 삭제는 204였고 세 응답의 본문은 비어 있었다.
- 컨트롤러와 `.http` 파일에 `ApiResponse` 및 `response.body.data` 사용이 남아 있지 않은지 `rg`로 확인했다.
- `.http` 파일은 갱신했으며, 기록된 수동 요청 실행 방법은 PowerShell·curl이다.

### 문제 / 해결

- 첫 테스트 실행에서 sandbox 네트워크 제한으로 Gradle 배포 파일을 받지 못했다. 허용된 환경에서 다시 실행해 통과를 확인했다.
- 수동 확인용 `bootRun`은 기본 포트 8080이 사용 중이라 시작하지 못했다. 로컬 18080 포트로 실행했다.
- PowerShell 5의 `Invoke-WebRequest`가 기본 IE 파서 문제로 응답을 읽지 못했다. `-UseBasicParsing` 옵션으로 재시도했다.
- 응답 상태 코드는 `ResponseEntity`에서 직접 지정하고 `@ResponseStatus`를 제거하기로 했다.
- 처음에는 미사용 `ApiResponse.java`가 남아 있었다. 삭제 여부를 별도로 승인받은 뒤 삭제하고 테스트를 재실행했다.
